# P4 API and Sign-in Implementation Plan

> **For agentic workers:** Use anthropic-skills:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Expose the use cases over `/v1` HTTP with the error contract from design section 8, sign-in through a trusted OIDC proxy (ADR 0006), and an OpenAPI definition.

**Architecture:** FastAPI app factory in `api/app.py` with routers per resource; `api/auth.py` resolves the actor; `api/errors.py` maps application errors to `{code, message, request_id, details, retryable}`. Read endpoints use `application/queries.py`, which authorizes and calls a read-model port implemented with SQL in `adapters/persistence/queries.py`. `entrypoints/admin.py` provisions tenants, projects, users and roles.

## Tasks

- [ ] **Task 1:** Read model: task list with candidate counts, task detail, candidates page, evidence blocks, record search (name, exact sequence, length, project; keyset cursor), record detail with versions and provenance, FASTA export with an escaped header. Integration tests.
- [ ] **Task 2:** Auth: trusted header plus proxy secret, development header, unknown users rejected, `X-Requested-With` on unsafe methods. Unit tests.
- [ ] **Task 3:** Routes from `packages/contracts/api/README.md`: uploads (declare, content, complete), jobs (get, list, candidates, document, cancel, reprocess), candidates (PATCH with `If-Match`, resolutions, archive), reviews, commits (`Idempotency-Key`), records (list, detail, export), files (original download after re-authorization), me, health. Error mapping for 400, 401, 403, 404, 409, 413, 422, 429.
- [ ] **Task 4:** Admin CLI and API entry point; commit `packages/contracts/api/openapi.json` generated from the app, with a test that fails when it is stale.
- [ ] **Task 5:** API integration tests: the full FASTA journey over HTTP, every error code, candidate payloads validate against `candidate.schema.json`.
